# INTGETION Taxonomy Service

Skill taxonomy for INTGETION JOB LIST: the canonical skill catalog (English and Russian names, 14 categories, Web3 marker skills), aliases, normalization of free text to a skill, fuzzy matching (pg_trgm), finding skills in a job text, and the suggestion queue for unknown skills.

Runs as its own HTTP process with its own tables and migrations. It calls no other service. Developed separately; the platform is not wired to it yet.

## Run

```bash
npm install
cp .env.example .env   # fill in values
npm run migrate        # skills tables, seed, pg_trgm
npm run dev            # http://localhost:4030
```

Checks: `npm run typecheck`, `npm test`. Integration tests run only when `DATABASE_URL` is set (and need `DATABASE_MIGRATION_URL`).

## How callers talk to it

Every request except `GET /health` needs `Authorization: Bearer <TAXONOMY_SERVICE_TOKEN>`. Admin routes (suggestions, seed) trust the caller to have checked admin rights. Errors are `{ "error": { "code", "message", "details?" } }`.

## API

| Method | Path | What |
|---|---|---|
| GET | `/health` | `{ ok }` |
| GET | `/v1/catalog` | categories, Web3 marker skills, similarity threshold |
| GET | `/v1/skills` | active skills |
| GET | `/v1/skills/stats` | counts and categories |
| POST | `/v1/skills/normalize` | `{ raw, source? }` → matched skill, or a new/updated suggestion |
| POST | `/v1/skills/match` | `{ raw }` → `{ slug }` or `null`, no suggestion written |
| POST | `/v1/skills/extract` | `{ text }` → `{ skillIds }` named in the text (max 10) |
| GET | `/v1/suggestions?cursor&limit` | pending suggestions (admin) |
| GET | `/v1/suggestions/count` | `{ pending }` |
| POST | `/v1/suggestions/:id/map` | `{ skillId }` → alias added (admin) |
| POST | `/v1/suggestions/:id/reject` | (admin) |
| POST | `/v1/jobs/seed-catalog` | re-seed the catalog |

## Data

Tables owned by taxonomy: `skills`, `skills_aliases`, `skill_suggestions`, function `skill_similarity`. Migrations in `migrations/`, applied by `npm run migrate`, tracked in `taxonomy_schema_migrations`:

- `0003_skills.sql` — generated by `npm run render-migration` from `src/db/skill-catalog.ts`; a test keeps them equal.
- `0019_skill_markers.sql` — skills part of platform migration 0019 (four more categories, Web3 skills).

Both are safe to run again on a live database: tables and indexes use `IF NOT EXISTS`, seed conflicts keep existing rows (admin edits survive), and forced RLS is lifted for the seed and restored. Checked against a non-superuser table owner.

Needs from the platform: type `moderation_status`, helper `public.enable_rls_deny_all`, roles `app_rw`, `anon`, `authenticated`. CI creates stand-ins from `test/sql/platform-stub.sql`.

`job_skills` belongs to jobs: filling a job's skills is the caller's job, using `/v1/skills/extract`.

## Packages inside

- `.` — service functions, `JOB_CATEGORIES`, `MARKER_SKILLS`, the skill catalog
- `./catalog` — the whole marker vocabulary: categories, skill categories, Web3 skills, employment types, seniority, sectors, perks, regions, catalog tags and quick filters (no database)
- `./server` — `createApp()` HTTP handler

Depends on `@intgetion/kit` (v0.2.0) by git tag.
